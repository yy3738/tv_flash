# TCL / 海信 真机验证清单（MVP 地基）

> 目的：在写正式代码前，用最小成本确认本方案在 TCL / 海信电视上是否成立。
> 五个验证项是整套方案的**地基**，任一关键项失败，都要回到设计重新评估。
> 建议对 **TCL 和 海信各测一台**，并记录机型、系统版本、Android 版本。

---

## 0. 前置条件（先确认能不能装 App）

| 项 | 操作 | 通过标准 | 失败怎么办 |
|---|---|---|---|
| 侧载 APK | U 盘拷贝一个测试 APK 到电视安装；或同局域网 `adb connect` 后 `adb install` | 能成功安装并启动 | 若完全禁止第三方安装，项目基本不可行（除非走厂商商店，但无障碍+自启必被拒） |
| 开发者选项 | 设置里找到"关于 → 版本号"连点开启开发者选项，打开 USB/网络调试 | 能开启、能 `adb` 连上（便于抓日志） | 不能开 ADB 也能靠 U 盘 + 日志文件，但排错变难 |

> 快速准备测试 APK：可以先不放自己的代码，直接安装一个**开源自动点击器 / 无障碍测试工具**来验证系统能力（省去先写 App），也可以只写一个最小 App：一个 AccessibilityService + 手动触发的按钮。

---

## 1. 无障碍服务能否开启

- **测什么**：第三方 App 能否声明并启用 `AccessibilityService`。
- **怎么测**：安装测试 APK → 设置里找到无障碍入口（TCL 常在「设置 → 更多设置 → 无障碍」，海信常在「设置 → 系统 → 辅助功能」）→ 找到我们的服务 → 开启。
- **通过标准**：列表里能看到服务名，能成功开启且状态显示"已开启"。
- **失败/注意**：入口被隐藏、需要密码、提示高危风险、开启后自动关闭 —— 逐条记录现象。这是**最关键的一项**。

## 2. takeScreenshot 能否截到图

- **测什么**：`AccessibilityService.takeScreenshot()`（需 Android 9 / API 28+）能否拿到真实画面。
- **怎么测**：服务里调用截图 API，把 Bitmap 存本地或显示出来。
- **通过标准**：截到当前屏幕真实画面，非全黑、非空、方向正确。
- **失败/注意**：返回错误码或黑屏 —— 记录（部分系统限制无障碍截图）。此时才考虑 MediaProjection 兜底，但它会牺牲"无人值守"。

## 3. dispatchGesture 能否点到第三方 App

- **测什么**：能否在**别的 App 界面**上注入点击。
- **怎么测**：电视打开一个第三方视频 App（如爱奇艺 TV / 云视听极光）→ 用 `dispatchGesture` 在一个已知按钮坐标注入一次点击 → 观察是否响应。
- **通过标准**：点击生效（按钮高亮 / 进入下一级页面）。
- **失败/注意**：手势无效或只在本 App 内有效 —— 记录。无 root 时这是唯一可控第三方 App 的手段。

## 4. BOOT_COMPLETED 自启

- **测什么**：开机自启是否被系统允许。
- **怎么测**：App 注册 `BOOT_COMPLETED` → 开机拉起前台服务 → 电视**彻底断电再开机** → 观察服务是否自动运行（看 App 内状态 / 日志 / 手机能否连上）。
- **通过标准**：重启后服务自动启动，手机可连接。
- **失败/注意**：被拦截 —— 记录，可能需要引导用户在"自启动管理 / 开机启动白名单"里手动放行。

## 5. 后台服务不被杀

- **测什么**：常驻服务长期存活能力。
- **怎么测**：服务运行后，切到其他 App、待机 10~30 分钟，再回来确认服务还在、还能连、注入仍有效。
- **通过标准**：长时间后仍可连接、功能正常。
- **失败/注意**：被系统清理 —— 需加入电池优化白名单 / 后台运行白名单；TCL / 海信 可能有额外限制，需记录具体路径。

---

## 附加验证（一并做，成本低、信息量大）

- **音量**：`AudioManager.adjustStreamVolume` 是否作用于电视真实音量。
- **返回/主页**：`performGlobalAction(GLOBAL_ACTION_BACK / HOME)` 是否有效。
- **熄屏/待机**：能否通过 API 让电视熄屏/待机（真正的关机/开机做不到）。
- **屏幕参数**：分辨率、DPI、横竖方向 —— 手机端坐标换算要用。
- **网络出站**：电视能否主动出站连接到外部 WSS（部分电视网络策略受限）—— 直接影响 NAS 中继能否连上。
