# 只做按需/低频截图，不做实时画面流

## 背景
手机端需要“看到电视画面”来辅助遥控。可选方案：实时屏幕镜像（类似 scrcpy / WebRTC 串流），或按需 / 低频截图。

## 决定
只做按需截图与低频自动刷新，不实现实时镜像流。

## 理由
- 产品核心价值是“遥控”，画面仅用于确认状态，低频足够。
- 实时镜像需要 MediaProjection + 硬件编码 + 低延迟传输，复杂度高一个量级；且 MediaProjection 每次进程重启都要重新授权，与“开机自启、无人值守”直接冲突。
- 低频截图的流量极小，正是“全经 NAS 中继”可行的前提（见 ADR-0002）。

## 后果
- 交互是“看一张图 → 点 → 再看一张图”的高延迟闭环，不如实时桌面流畅，但符合“帮别人操作”的场景。
- 截图依赖无障碍 takeScreenshot（Android 9+），而非 MediaProjection（见 ADR-0003）。
